# Release 0.10.0 recovery

This change implements the workflow fixes for the failures after [release PR #262](https://github.com/rocketclimb/rocketicons/pull/262) merged. The website deployed, but npm publication and branch synchronization failed.

## What went wrong and what changed

| Failure                                                                                                                                                     | Implemented fix                                                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The first publication run could not find the successful Cut Release run. The same lookup succeeded on retry; the cause of the original miss is unconfirmed. | Read the exact run URL saved in the release PR, then verify its repository, workflow, source commit and successful status. Retry failed API reads four times. Older PRs without the URL use a bounded, paginated search. Existing artifact metadata checks remain in place.                                          |
| Squash merging replaced the release's ancestry, causing add/add conflicts when syncing back to `develop`.                                                   | Verify the squash commit and prepared release head contain identical files, and that the cut source is already in `develop`. Record their shared history in a local bridge commit, then perform a normal merge. Preserve newer changes on both branches. Real conflicts abort; pushes never force-replace `develop`. |
| npm returned E404 on `@rocketicons/utils@0.8.0`. The other packages were never reached.                                                                     | Add repository metadata to all four scoped package manifests for future trusted publication. Add an optional `NPM_TOKEN` recovery path for existing archives that lack it. Check every archive and existing registry version before publishing the first package.                                                    |
| The retry created a tag before npm failed, making another attempt fail on the existing tag.                                                                 | Reuse a tag only if it points to the original release merge commit. Resume partially published packages only if their names, versions and SHA-512 archive integrity match exactly. Apply this to all five packages.                                                                                                  |

At 17:37 UTC on September 26, the live registry contains the exact prepared `utils@0.8.0` and `tailwind@0.8.0` archives. A later [fourth attempt](https://github.com/rocketclimb/rocketicons/actions/runs/36251805921/attempts/4) now fails on `toolkit@0.2.0`; toolkit, MCP and rocketicons still need publication.

The npm error alone does not establish which account permission or trusted-publisher setting was wrong. Missing repository metadata is a confirmed configuration gap: [npm requires the repository URL to match for GitHub trusted publishing](https://docs.npmjs.com/trusted-publishers/).

## Recover the existing release after merging this fix

1. Ensure npm authorizes the remaining packages. Where trusted publishing cannot bootstrap an unpublished package, configure the repository's optional `NPM_TOKEN` secret with publish/create access to those packages. If this token is provided, legacy archives without repository metadata use token authentication with provenance disabled; their bytes remain unchanged. Without a token, the workflow retains npm's existing trusted-publishing behavior. No credentials or npm account settings are changed by this PR.
2. Run **Release Packages** manually on **main**, with `release_pr` set to `262`. This loads the updated workflow while selecting the original merged release, versions and artifacts. Rerunning the old failed job would load the old workflow.
3. The workflow resolves Cut Release run `36250310169`, validates its metadata, reuses `v0.10.0-release` only at `86943b1493ac82016e18ef535c8e03d4451a0cdb`, and publishes or verifies each package in order. It creates the GitHub release only after all five packages are confirmed.
4. Merging this fix automatically runs **Sync main into develop**, including the previous release's history and the fix itself. The workflow also supports a manual run on `main` if a retry is needed.
5. Confirm the public npm versions and a fresh installation after publication. This PR's local tests do not exercise live npm writes or prove package permissions.

| Package                 | Prepared version | Publish order |
| ----------------------- | ---------------- | ------------- |
| `@rocketicons/utils`    | `0.8.0`          | 1             |
| `@rocketicons/tailwind` | `0.8.0`          | 2             |
| `@rocketicons/toolkit`  | `0.2.0`          | 3             |
| `@rocketicons/mcp`      | `0.2.0`          | 4             |
| `rocketicons`           | `0.4.0`          | 5             |

For future cuts, repository metadata is included in the packages. Configure each npm package's trusted publisher for GitHub organization **rocketclimb**, repository **rocketicons**, workflow **release.yml**, with direct publishing enabled. The workflow uses Node 24, npm 11.19 and `id-token: write`. The optional token is a fallback, not a substitute for configuring the trusted publisher. Those npm account settings cannot be installed by changing repository files.

Recovery intentionally stops if artifacts have expired, a tag points elsewhere, an existing npm version has different bytes, or Git finds genuine competing edits. Branch sync searches the latest 30 main commits since the shared ancestor for a release PR; if none is found, it attempts an ordinary merge and leaves conflicts for review. It does not guess release history.

The existing release guards and version-alignment tests still run.
